# Messages

Every piece of text a person reads in the app comes from these files. Code never contains
user-visible English; it calls a message function, and the function returns the text in the
language the page is rendering in.

```tsx
import { m } from '@/paraglide/messages.js'
;<Button>{m.action_save()}</Button>
toast.success(m.items_copied_to_list({ listName }))
```

The functions are generated by [Paraglide JS](https://paraglidejs.com) from these JSON files
into `src/paraglide/` (not committed). `pnpm dev`, the build, vitest and Storybook generate
them on their own; run `pnpm i18n:compile` for anything else on a fresh checkout.

## Files

One file per area and language: `messages/<locale>/<area>.json`. `en` is the source; every
key in an `en` file must exist in the same `fr` file. Areas are listed in
`project.inlang/settings.json`; add a line there when you add an area file.

| File                                                              | Holds                                                                                                         |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `common`                                                          | Words reused across areas: `action_*` buttons, `state_*`, labels for priorities, list types, days, name lists |
| `shell`                                                           | Page titles (`page_*`), sidebar and breadcrumbs (`nav_*`), error and not-found pages                          |
| `settings`, `auth`, `items`, `lists`, `purchases`, `intelligence` | That area's screens                                                                                           |
| `misc`                                                            | Anything that fits none of the above                                                                          |

All files share one namespace, so a key must be unique across them.

## Keys

- `snake_case`, starting with the area: `items_add_dialog_title`, `lists_delete_confirm`.
  Shared words start with `action_`, `state_` or `word_` and live in `common`.
- Name the place and the role, not the English wording: `items_claim_button`, not
  `items_claim_this_gift`. Wording changes; the place does not.
- Reuse a `common` key only for the same word in the same sense (a Cancel button is always
  `action_cancel`). Do not reuse a sentence from another screen because the English happens to
  match; the French may need to differ.

## Writing messages

- **Whole sentences.** Never assemble a sentence from pieces in code. Put the variable inside
  the message: `"items_copied_to_list": "Copied to {listName}"`.
- **Plurals** use a variant, never `count === 1 ? ... : ...` in code:

  ```json
  "count_days": [
  	{
  		"declarations": ["input count", "local countPlural = count: plural"],
  		"selectors": ["countPlural"],
  		"match": { "countPlural=one": "{count} day", "countPlural=*": "{count} days" }
  	}
  ]
  ```

  Always end with the `*` case. French counts 0 and 1 as singular.

- **Possessives and names.** English "{name}'s list" must be one message with `{name}` in it,
  so French can say "la liste de {name}". Where the code chose between "your" and
  "{name}'s", write two messages.
- **Formatting inside text** (a link or bold in the middle of a sentence): split around the
  element only if each part reads as a whole phrase; otherwise keep one message and render it
  with `ParaglideMessage` markup.
- Dates, numbers and "3 days ago" go through `src/lib/i18n/format.ts`; names of priorities,
  list types and months through `src/lib/i18n/labels.ts`.

## Never build text when a module loads

```ts
// Wrong: evaluated once, in whatever language the server was rendering at that moment.
const LABELS = { low: m.priority_low(), high: m.priority_high() }

// Right: evaluated on each call, in the current language.
function label(p: Priority) {
	switch (p) { ... }
}
```

The same goes for arrays of options, nav tables, column definitions and zod schemas with
messages: make them functions, or store `() => m.key()` and call it when rendering.

## French

French is written with "vous". An unfinished language is compiled in but not offered to
users; see `READY_LOCALES` in `src/lib/i18n/locales.ts`. To review it on a preview build, set
`VITE_PREVIEW_LOCALES=fr`.

## Lint

`i18next/no-literal-string` fails on hardcoded JSX text and readable attributes (`title`,
`placeholder`, `aria-label`, `alt`, ...) in the directories listed as `I18N_EXTRACTED` in
`eslint.config.js`. It does not see strings passed to functions (toasts, `throw new Error`,
confirm dialogs), so check those by hand. Use an `eslint-disable-next-line` with a reason for
text that is truly not for users.
